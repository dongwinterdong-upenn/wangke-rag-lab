# 考试须知

本仓库用于 2026 年 10 月 23 日的 RAG 实操考试，时间是北京时间 14:00 到 19:00，共 5 小时。任务是在自己电脑上部署网课平台，给答疑助手懂妈加上 RAG，评测改造前后的效果，19:00 前把提交材料发到群里。

## 一 开考前

能提前做的先做完，开考后的 5 小时全部用在开发上：

1. 照 [本机部署教程](本机部署教程.md) 第二节装好 Docker Desktop 与 Git，配置镜像加速地址。Windows 装 WSL 2 要重启电脑。
2. 照第三节下载代码。

## 二 DeepSeek 密钥

- 开考时老师在群里发一把实训专用的 DeepSeek 密钥，填进 `.env` 的 `DEEPSEEK_API_KEY`。
- 全体考生共用这一把，余额有限。评测脚本的并发不要超过 5，不要反复整套重跑，调试时先用十几道题。
- 密钥只写在 `.env` 里。`.env` 不提交，代码，截图，提交包里都不能出现密钥。
- 密钥报错或余额用完，在群里说，不要自己另找密钥。

## 三 建议的时间安排

| 时间 | 做什么 |
| --- | --- |
| 14:00 到 14:45 | 部署平台，在学员端问懂妈几个问题，读开发要求 |
| 14:45 到 15:15 | 写评测脚本，先用它测一遍**改造前**的懂妈，记下数字 |
| 15:15 到 17:45 | 开发 RAG：解析资料，切片，建索引，检索，生成，出处 |
| 17:45 到 18:15 | 用同一个评测脚本测改造后的懂妈 |
| 18:15 到 18:50 | 写设计说明与评测报告，截图，打包 |
| 18:50 到 19:00 | 在群里提交 |

改造前的数字一定要在动手改懂妈之前测，改完再想测就要把旧版本切回来。

## 四 任务里的“发布”指什么

把 `compose.yaml` 里的 `dongma` 服务换成新的 RAG 版懂妈，执行 `docker compose up -d --build` 后，四个服务正常运行，在平台学员端的答疑页提问能拿到带出处的回答。只在自己电脑上运行，不需要部署到服务器，也不需要推送到 GitHub。

## 五 提交

19:00 前在群里发一个 zip 包，文件名是 `姓名_懂妈RAG.zip`，里面包括：

| 内容 | 位置 |
| --- | --- |
| 新的懂妈服务全部代码，包括 Dockerfile 与建索引的代码 | `dongma` 目录，或者新建的目录 |
| 改动后的编排文件 | `compose.yaml` |
| 评测脚本，评测原始记录 | `eval` 目录 |
| 评测结果报告：检索命中率，答题正确率，响应时间，改造前后对比 | `eval/评测报告.md` |
| 设计说明，附 5 个提问的截图 | `docs/RAG设计说明.md`，截图放 `docs/截图` |

不要放进 zip 的：`.env`，模型文件，索引文件，`course` 目录，`node_modules`。

各项要求的细节见 [RAG 实训开发要求](RAG实训开发要求.md) 第六到第八节。

在仓库根目录下打包：

```bash
# macOS 与 Linux
zip -r 姓名_懂妈RAG.zip dongma compose.yaml eval docs deploy -x "*/node_modules/*" "*/models/*" "*/index/*"
```

```powershell
# Windows PowerShell
Compress-Archive -Path dongma, compose.yaml, eval, docs, deploy -DestinationPath 姓名_懂妈RAG.zip
```

新建的目录要一并列进去。打包后打开 zip 看一眼，确认里面没有 `.env`，也没有模型和索引文件。
