# 本机部署教程

在自己的电脑上用 Docker 把网课平台整套跑起来：数据库，平台后端，学员端，代理端，平台后台，以及答疑助手懂妈。Windows，macOS，Linux 步骤相同，只有安装 Docker 那一步不同。

每一步给出要执行的命令与应该看到的结果。结果不一样时先看第八节故障排查。

## 一 电脑要求

- 内存 8G 以上，给 Docker 分 4G 以上。
- 磁盘空余 15G 以上，镜像与依赖约 6G，仓库约 70M。
- 能上网。首次构建要下载镜像与依赖。
- 一把 DeepSeek 密钥，由老师单独发放，不要提交进仓库，也不要发到群以外的地方。

## 二 安装 Docker 与 Git

### Windows 10 与 11

1. 在 BIOS 里打开 CPU 虚拟化，多数电脑默认已开。
2. 以管理员身份打开 PowerShell，执行 `wsl --install`，按提示重启。
3. 到 Docker 官网下载 Docker Desktop for Windows，安装时勾选 Use WSL 2，装完重启。
4. 安装 Git for Windows，一路默认。

### macOS

1. 下载与芯片对应的 Docker Desktop：苹果芯片选 Apple Silicon，较早的 Mac 选 Intel chip，拖进应用程序后打开。
2. 在终端执行 `git --version`，没装会提示安装命令行工具，按提示装。

### Linux

照 Docker 官方文档装 Docker Engine 与 compose 插件，再执行 `sudo usermod -aG docker $USER`，注销重新登录。

### 检查

打开 Docker Desktop，等左下角显示 Engine running。然后在终端执行，Windows 用 PowerShell：

```bash
docker --version
docker compose version
git --version
docker run --rm hello-world
```

应依次看到三行版本号，以及 `Hello from Docker!`。

在 Docker Desktop 的 Settings → Resources 里把内存调到 4G 以上。

### 国内网络

在国内直接连不上 Docker Hub，`hello-world` 那一步卡住或报 `timeout` 就是这个原因，要先配置镜像加速地址。打开 Docker Desktop 的 Settings → Docker Engine，在已有配置的最外层大括号里加上 `registry-mirrors` 这一项：

```json
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.m.daocloud.io",
    "https://docker.xuanyuan.me",
    "https://docker.1panel.live",
    "https://dockerproxy.net"
  ]
}
```

点 Apply & restart，再执行一次 `docker run --rm hello-world`。Linux 上这一项写在 `/etc/docker/daemon.json`，改完执行 `sudo systemctl restart docker`。

2026 年 10 月 23 日从国内服务器实测：前两个地址与最后一个地址都能拉下本仓库要用的六个镜像，前两个每秒 6 到 10 MB，最后一个约 2 MB。中间两个只测过一个小镜像，作为备用。Docker 按顺序尝试，前一个不通会自动换下一个。

Maven 依赖与 npm 包在构建时默认走阿里云与 npmmirror 的国内镜像，不用另外设置。

## 三 拿到代码

```bash
git clone https://github.com/dongwinterdong-upenn/wangke-rag-lab.git
cd wangke-rag-lab
```

国内访问 GitHub 网页与 `git clone` 时常很慢。克隆失败时直接下载代码压缩包，约 50MB，解压后进入解压出的 `wangke-rag-lab-main` 目录：

https://codeload.github.com/dongwinterdong-upenn/wangke-rag-lab/zip/refs/heads/main

以后的命令都在这个目录里执行。

## 四 填写配置

复制配置模板：

```bash
cp .env.example .env
```

Windows 的 PowerShell 也能用 `cp`。用记事本或任意编辑器打开 `.env`，把老师发的密钥填在 `DEEPSEEK_API_KEY=` 后面，等号两边不留空格，保存。其余各项都能用默认值。

`.env` 已经写进 `.gitignore`，不会被提交。

## 五 启动

```bash
docker compose up -d --build
```

第一次要下载约 650MB 镜像，再编译后端与三端前端，配好镜像加速后一般 10 分钟左右，网慢时要 20 分钟。之后再执行只要几十秒。完成后查看状态：

```bash
docker compose ps
```

四个服务都应在运行，其中 `mysql`，`backend`，`dongma` 三个带 `(healthy)`：

| 服务 | 作用 |
| --- | --- |
| `mysql` | 数据库，首次启动时自动建库，灌入 6 套测评卷 400 道题与两个开发账号 |
| `backend` | 平台后端 |
| `dongma` | 懂妈答疑服务 |
| `web` | 三端页面，对外端口 8080 |

刚启动时 `backend` 会显示 `(health: starting)`，等一分钟再看。

## 六 使用

浏览器打开 http://localhost:8080 ，会跳到学员端。

| 角色 | 地址 | 手机号 | 密码 |
| --- | --- | --- | --- |
| 学员 | http://localhost:8080/study/ | 13900000001 | Lab@student2026 |
| 平台超管 | http://localhost:8080/admin/ | 13800000000 | Lab@admin2026 |

登录页选密码登录。这两个账号只在本机有效。

验证三件事：

1. 学员登录后进入答疑页，提一个课程问题，例如“RAG 是什么”，几秒内懂妈开始逐字作答。
2. 学员端测评页能看到 6 套卷，任选一套开考并交卷，能看到分数。交卷后的 AI 测评报告要过半分钟左右才生成。
3. 平台超管登录后台，在考试管理里能看到 6 套卷，共 400 道题。

本机部署有几处与线上不同：

- 没有短信与支付，注册新学员与购买课程走不通，用上面的学员账号。
- 没有课程视频，课程页面里没有可播放的讲次。
- 每个学员每天在答疑页最多提 20 问，评测请直接调懂妈接口，见下一节。

## 七 开发时常用的操作

### 直接调懂妈

懂妈在本机的 28790 端口，只对本机开放。令牌是 `.env` 里的 `DONGMA_API_TOKEN`，默认值是 `lab-dongma-token-2026`：

```bash
curl -N http://127.0.0.1:28790/ask \
  -H "Authorization: Bearer lab-dongma-token-2026" \
  -H "Content-Type: application/json" \
  -d '{"question": "第 9 讲讲了什么？", "history": []}'
```

输出是一串 `data:` 开头的行，最后一行带 `"done":true`。接口约定见 `docs/RAG实训开发要求.md` 第三节。Windows 的 PowerShell 里请用 `curl.exe`，并把整条命令写在一行。

### 改了懂妈之后

- 只改了 `dongma/workspace` 下的 markdown：不用重启，懂妈每次提问都会重新读。
- 改了代码或 `deploy/dongma.Dockerfile`：执行 `docker compose up -d --build dongma`。
- 改了平台后端或前端：执行 `docker compose up -d --build backend` 或 `docker compose up -d --build web`。

### 看日志

```bash
docker compose logs -f dongma
docker compose logs -f backend
```

按 Ctrl+C 退出，服务不受影响。

### 查数据库

数据库在本机的 3307 端口。用数据库客户端连 127.0.0.1:3307，用户 `wangke`，密码是 `.env` 里的 `MYSQL_PASSWORD`，默认 `lab-wangke-2026`，库名 `wangke`。也可以直接进容器：

```bash
docker compose exec mysql mysql -uwangke -plab-wangke-2026 wangke
```

学员的提问与懂妈的回答在 `qa_ticket` 与 `qa_message` 两张表里。

### 停止与重置

| 操作 | 命令 |
| --- | --- |
| 停止，数据保留 | `docker compose stop` |
| 再次启动 | `docker compose up -d` |
| 删掉容器与数据库数据，下次启动重新建库 | `docker compose down -v` |

电脑重启后，Docker Desktop 打开时各服务会自动起来。

## 八 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 拉镜像报 `timeout` 或 `TLS handshake` | 国内访问 Docker Hub 不稳，按第二节配置镜像加速地址 |
| 构建卡在 `mvn` 或 `pnpm install` 很久 | 网络慢，等一等。在国外的电脑上可以改用官方源：`docker compose build --build-arg MAVEN_MIRROR=https://repo.maven.apache.org/maven2 --build-arg NPM_REGISTRY=https://registry.npmjs.org` |
| `port is already allocated` | 8080，3307 或 28790 被别的程序占用。在 `.env` 里改 `WEB_PORT`，`MYSQL_PORT` 或 `DONGMA_PORT`，再 `docker compose up -d` |
| `dongma` 一直在 Restarting | 没填 DeepSeek 密钥。`docker compose logs dongma` 能看到“缺 DEEPSEEK_API_KEY”。填好后 `docker compose up -d` |
| 懂妈的回答都变成“已转人工” | 懂妈没在运行，或调用出错。看 `docker compose logs backend` 里带“懂妈”的那几行 |
| `backend` 一直不是 healthy | 看 `docker compose logs backend`。最常见的是数据库还在初始化，等一两分钟 |
| 浏览器打不开页面 | `docker compose ps` 确认 `web` 在运行，地址用 http 不是 https |
| 登录提示密码错误 | 选的是验证码登录，切到密码登录 |
| 想从头再来 | `docker compose down -v` 后重新 `docker compose up -d --build` |
| Windows 上 `mysql` 起不来，日志里有 `\r` | 克隆时换行被改成了 CRLF。删掉目录，执行 `git config --global core.autocrlf false` 后重新克隆 |
