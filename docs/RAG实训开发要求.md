# RAG 实训开发要求

给网课平台的课程答疑助手“懂妈”加上检索增强生成，让她能从全部课程资料里找到依据再作答，并告诉学员答案出自哪里。

## 一 现状

学员在平台学员端的答疑页提问，请求链路如下：

1. 浏览器把问题发给平台后端的 `POST /api/qa/ask`。
2. 后端先查平台自带的问答库，本机部署里问答库是空的，一律查不到。
3. 后端调懂妈的 `POST /ask`，边收边把回答转给浏览器，收完存进库里。
4. 懂妈把问题连同固定的系统提示词发给 DeepSeek，流式返回。

懂妈的代码在 `dongma/serve.mjs`，170 行。系统提示词由 `dongma/workspace` 下三个文件拼成：

| 文件 | 内容 |
| --- | --- |
| `IDENTITY.md` | 她是谁，叫什么，什么口吻 |
| `SOUL.md` | 答疑规矩：只依据课程内容作答，答不了就转人工，不替课程做承诺 |
| `AGENTS.md` | 全部课程知识，是一份约 1.6 万字的人工摘要 |

这种做法有三个问题：

- 知识只有这份摘要。课件 536 页，讲义 213 页，转写 22.6 万字，绝大部分细节她都不知道。
- 摘要按录屏场次组织，平台按讲次组织。学员问“第 3 讲讲了什么”，她答的是第 3 场录屏，也就是平台第 5 到 8 讲的内容。
- 每次提问都把整份摘要发给模型，资料再多一倍就放不下了。

## 二 目标

把懂妈改造成基于检索的答疑：先从全部课程资料里检索出与问题相关的片段，再让模型只依据这些片段作答，并标明出处。

## 三 必须遵守的接口

平台后端怎么调懂妈是定死的，平台代码不改。新的懂妈必须实现同一个接口，替换掉 `dongma` 这个服务后平台照常工作。

### 请求

```
POST /ask
Authorization: Bearer <DONGMA_API_TOKEN>
Content-Type: application/json

{"question": "学员的问题", "history": [{"role": "user", "content": "…"}, {"role": "assistant", "content": "…"}]}
```

- 令牌不对返回 401。
- `history` 是同一个提问单里之前的来回，可能为空数组。
- `question` 为空返回 400。

### 响应

响应头 `Content-Type: text/event-stream`，正文是一串 `data:` 事件，每个事件一行 JSON，事件之间空一行：

```
data: {"delta": "第一段文字"}

data: {"delta": "第二段文字"}

data: {"done": true, "text": "完整回答"}
```

- `delta` 是一段新增的回答文字，平台收到就转给学员看。
- `done` 只能在回答完整时发，`text` 是完整回答。平台以收到 `done` 为准判断回答是否完整，没收到就当作半截，撤掉已显示的文字并转人工。
- 出错时发 `{"error": "原因"}` 后结束。回答被截断也要发 `error`，不能发 `done`。
- 平台从发出请求到收到响应头最多等 60 秒，检索要在这之内开始返回。

### 健康检查

`GET /health` 返回 200 与一个 JSON。编排文件用它判断服务是否就绪。

### 运行环境

| 环境变量 | 含义 |
| --- | --- |
| `DEEPSEEK_API_KEY` | DeepSeek 密钥 |
| `DONGMA_API_TOKEN` | 与平台约定的令牌 |
| `DONGMA_API_HOST` `DONGMA_API_PORT` | 监听地址与端口。考试服务器上见 `~/lab.env`，本机 Docker 部署时容器里是 `0.0.0.0` 与 18790 |

## 四 语料

全部在 `course` 目录，说明见 `course/README.md`：

- `course/课件`：5 份 PDF。
- `course/讲义`：5 份 PDF。
- `course/转写`：5 场录屏的逐字转写，每句带讲次与讲内秒。
- `course/目录`：16 讲 90 节的目录，每节带讲内起止时间与摘要。
- `course/知识点全览.md`：现有的知识摘要。

`course/测评` 是评测集，不能进检索语料。

## 五 功能要求

### 必须做到

1. **入库**：把第四节的全部语料处理成可检索的片段。PDF 按页或页内段落切，转写按时间窗口或语义切，每个片段记下出处：是哪份资料，课件与讲义记页码，转写记讲次与讲内秒。
2. **索引与检索**：给片段建索引，按问题检索出最相关的若干片段。DeepSeek 没有向量化接口，向量要用本机能跑的模型来算，例如 BGE 系列的中文模型，或者用关键词检索，也可以两者结合。不许用 DeepSeek 以外的付费接口。
3. **生成**：把检索到的片段交给模型，要求它只依据这些片段作答。片段里没有依据的问题，回答“课程里没有讲到”并建议转人工，不许编。
4. **出处**：回答末尾列出依据的出处，格式统一，学员拿着能找回原文：
   - 转写写成 `第 6 讲 12:30`，讲次与讲内时间对应平台播放器。
   - 课件与讲义写成 `课件 Day 3 第 45 页` 或 `讲义 Day 3 第 12 页`。
5. **讲次理解**：问“第 N 讲”“某一节”时，按平台的 16 讲理解，不是按录屏场次。
6. **人设不变**：`IDENTITY.md` 与 `SOUL.md` 的身份与规矩保留，`AGENTS.md` 里的知识摘要可以去掉或改作检索语料之一。
7. **多轮**：利用 `history` 理解追问，例如“那第二点呢”。
8. **部署**：语言与框架不限。考试服务器上，新服务监听 `~/lab.env` 指定的懂妈端口，平台已经接好，给出建索引与启动的命令，写进设计说明。本机 Docker 部署时，新服务替换 `compose.yaml` 里的 `dongma` 服务，`docker compose up -d --build` 一条命令就能起来。索引文件不进版本库。
9. **资源**：不需要显卡。考试服务器上每人内存上限 1.5G，见考试服务器指南第五节。

### 加分

- 检索结果重排，问题改写，混合检索。
- 学员问的是课程外的话题，例如 `AIGC_OPEN` 那套卷的数据标注，文生图，能识别出来并说明课程没讲。
- 改平台学员端，让回答里的出处可以点击，转写出处跳到播放器对应时间，PDF 出处打开对应页。这一项要改 `web/apps/student` 与平台后端，改动写进设计说明。
- 资料更新后只增量重建变化的部分。

## 六 评测

用 `course/测评/测评题库.json` 衡量效果，评测脚本与原始记录放在 `eval` 目录。作答与时延直接调懂妈的 `/ask`：考试服务器上地址是 `http://127.0.0.1:$DONGMA_API_PORT/ask`，令牌是环境变量 `DONGMA_API_TOKEN`。本机 Docker 部署时端口是 28790，令牌是 `.env` 里的 `DONGMA_API_TOKEN`。不要经平台答疑页批量提问，那里每个学员每天限 20 问。

DeepSeek 密钥是全体共用的，评测并发不要超过 5。调试时先用十几道题，确认脚本对了再跑整套。

改造前的懂妈要先测：在改动 `dongma` 之前，用同一个评测脚本测一遍现有版本，把数字与原始记录留好。

### 检索命中率

300 道课程题都带 `出处讲次` 与 `出处讲内秒`。把题干作为问题去检索，看前 k 个结果里有没有命中出处：转写片段与出处同一讲，并且片段覆盖的时间与出处时间相差 60 秒以内，就算命中。报告 k 取 1，3，5，10 时的命中率，并按四章分别统计。

`/ask` 不返回检索结果，这一项由评测脚本直接调用自己的检索代码，或者给服务加一个只在本机用的调试接口。改造前的懂妈没有检索，这一项只报改造后。

作为参考，最简单的做法是把转写按讲次切成 60 秒的窗口，用题干直接做关键词检索或用 bge-small-zh-v1.5 向量检索，前 5 命中率都在五成左右。

### 答题正确率

300 道课程题逐题发给懂妈，问题统一写成下面这样，大括号里的部分按题目替换：

```
下面是一道{单选题|多选题，可能有多个正确选项|判断题，正确答 T，错误答 F}。第一行只写选项字母。第二行写这道题的知识点出自平台第几讲的什么时间，格式：出处：第 N 讲 mm:ss

{题干}
A. {选项}
B. {选项}
……
```

从回答里取两项打分：

1. **选项正确率**：第一行的选项字母与 `答案` 比对。单选与判断题字母相同算对，多选题字母集合完全相同算对。
2. **出处正确率**：回答里第一个“第 N 讲 mm:ss”，N 等于 `出处讲次`，并且时间与 `出处讲内秒` 相差 120 秒以内，算对。另报只看讲次对不对的“出处讲次正确率”。

这些题考的是工程判断，DeepSeek 不看课程资料也能答对大部分，所以改造前的选项正确率就接近满分，这一项用来确认改造没有把作答能力弄坏。能体现检索效果的是出处正确率：改造前的懂妈只知道录屏场次，给不出平台讲次与讲内时间。

`AIGC_OPEN` 的 100 道题考的是课程外的内容，用同样的写法提问，单独报告懂妈有多少题说明了课程没讲，有多少题硬答。

### 响应时间

记录每题的首字时间与完整回答的时间，报告中位数与 90 分位数。首字时间要在 60 秒以内，否则平台会判超时。

### 评测报告

`eval/评测报告.md` 至少包括下面这张表，改造前与改造后各一行，数字都由交付的脚本跑出来：

| 版本 | 检索命中率 前1，前3，前5，前10 | 选项正确率 | 出处讲次正确率 | 出处正确率 | 课程外题说明课程没讲的比例 | 首字时间 中位，90 分位 | 完整回答 中位，90 分位 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 改造前 | 不适用 | | | | | | |
| 改造后 | | | | | | | |

另附按四章分开的检索命中率，以及出处答错的若干典型例子与原因分析。

## 七 交付物

1. 代码：新的懂妈服务与建索引的代码，以及改动后的 `compose.yaml`。
2. 评测：`eval` 目录下的评测脚本，原始记录，以及 `eval/评测报告.md`。
3. 设计说明 `docs/RAG设计说明.md`：切片方法，用的向量模型与检索方法，提示词，出处怎么生成，几次关键调整前后的评测数字，没解决的问题。
4. 演示：在平台学员端的答疑页提 5 个问题，覆盖课件细节，讲次问答，多轮追问，课程外问题，截图放在 `docs/截图`，并在设计说明里引用。

提交方式见 [考试须知](考试须知.md)。

## 八 验收

- 按设计说明里的命令建索引并启动新懂妈，自己那套平台的学员端答疑页能拿到带出处的回答。
- 第三节的接口逐条成立：无令牌返回 401，正常回答以 `done` 结束，出错以 `error` 结束。
- 回答里的出处能在资料里找到原文，讲次与讲内时间对得上平台的 16 讲。
- 评测数字能用交付的脚本复现。
- 提交的代码与文件里没有密钥，测评集没有进入检索语料。

## 九 国内网络下取依赖与模型

下面几条 2026 年 10 月 23 日从国内服务器实测过：

- **Docker 镜像**：按 [本机部署教程](本机部署教程.md) 第二节配置镜像加速地址。自己写的 Dockerfile 用 `python:3.12-slim`，`node:24-slim` 这类官方镜像都能经加速地址拉到。
- **Python 包**：pip 加 `-i https://mirrors.aliyun.com/pypi/simple/`，写在 Dockerfile 里。
- **向量模型**：huggingface.co 在国内不通。用 Hugging Face 生态的库时设环境变量 `HF_ENDPOINT=https://hf-mirror.com` 与 `HF_HUB_DISABLE_XET=1`，后一个不设，新版 huggingface_hub 下模型会报 401。也可以从魔搭 modelscope.cn 下载，魔搭更快。
- **PyTorch**：从 PyPI 直接装的 Linux 版 torch 会带上几 GB 的显卡依赖。只用 CPU 时加 `--index-url https://download.pytorch.org/whl/cpu`，或者选 fastembed 这类基于 ONNX Runtime 的库，不装 torch。
- **内存**：向量化要分批，批大小 16 左右。一次把全部片段送进模型会超出 Docker 的内存，容器被系统强行结束，退出码是 137。

实测参考：fastembed 加 bge-small-zh-v1.5，镜像 228MB，在 2G 内存限制下按批大小 16 运行，模型经 hf-mirror 下载 13 秒，608 个转写窗口向量化约 4 分钟。模型文件与索引放在 `.gitignore` 里已忽略的 `models` 与 `index` 目录。
