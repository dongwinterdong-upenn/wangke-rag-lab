## 1. L1 认知与环境(7.13)

> 注意:本讲缺开头 48 分钟(推测含开营与导论,内容未知,不写)与结尾 34 分钟。以下知识点均出自录到的 97.8 分钟。

### 1.1 思维链(CoT)与推理模型

- **CoT 的本质**:把大模型的"一次输出"变成"先推理再作答的两段输出"。讲师用经典的**苹果算术题**逐步演示:咖啡馆原有 23 个苹果,吃掉 20 个剩 3 个,又买 6 个是 9 个——让模型把中间步骤写出来,"比直接去输出一个最终的回答,准确命中的概率会大很多","这就是实验所得的"。结论口径:CoT 的作用是**让模型有更多过程可依赖**,中间步骤本身在提升最终答案的命中率(开场 00:00–00:02 段)。
- 由 CoT 引出**推理模型**谱系:o1、DeepSeek-R1 作为"把思维链内化到训练里"的代表被点名(屏幕同帧出现 Chain-of-Thought / o1 / DeepSeek-R1)。
- ReAct 在本讲被首次提及(约 01:33 段),此时只是埋名词,完整展开在 L7。

### 1.2 幻觉:成因与抑制

- **成因**在 00:04:23 附近讲出:模型的生成机制决定了它会"编"——这一条与 L4 01:14:30 用 next token prediction 重推幻觉成因形成前后呼应(L1 讲现象与对策,L4 讲机理)。
- **抑制方法**集中在 00:07:24–00:08:33,讲师明确报了"抑制模型幻觉的第二种方法"的措辞,即方法是**成组给出**的(检索增强/让模型说依据一类;精确到第几种对应什么,转写噪声较大,不硬写)。注意:市面上流传的"事前/事中/事后三阶段抑制"框架是后来分析报告的归纳,**不是讲师原话**。
- 00:18:27 附近有一句定位:"这是一个我们说的技术依赖与合规性的要求"——幻觉与合规被放在同一个风险叙事里讲。

### 1.3 模型格局与选型

- 讲师用 **Artificial Analysis**(第三方模型评测对比站,屏幕 26 帧)带着看当前模型格局:GPT、Claude(含 Claude Fable 5,屏幕 11 帧)、Gemini、DeepSeek、GLM、Qwen、Llama、Kimi 全部出场。教学意图是**让学员会看排行榜、会比模型**,而不是背结论。
- 国产模型给足了戏份:DeepSeek(deepseek-v4-pro / deepseek-v4-flash 两档在 01:03 段出现)、GLM-5.2、通义千问。这也为后面几讲"主力用 DeepSeek API"作了铺垫。

### 1.4 模型的"体格":参数量、量化与显存

这是本讲最"面试向"的一段,三个知识点连着讲:

1. **参数量单位**(00:56:45 起):B = billion,十亿参数;并给出**本地部署档位表**——多大内存/显存能跑多大的模型(如 8G 内存跑 1.5B 一类的档位对照),配套点名了本地部署工具 **Ollama 与 vLLM**(屏幕各 10 帧)。
2. **量化**(00:58:36 起):FP16、INT4 等精度对显存的影响;讲师在这里说了"**这个如果你去面试的时候经常考**"。
3. **显存估算公式**(01:00:44):**显存 ≈ 参数量 × 每参数字节数 × 1.2**(8B 模型按 FP16 即 8B×2×1.2≈19GB)。注意:L4 01:50:36 重讲这个话题时用的是**不带 1.2 系数的 ×2 速算**(7B→14GB、13B→26GB、70B→140GB),两讲口径不一致,引用时要分清。

### 1.5 Embedding 首次登场

约 01:07:39 出现 Embedding 概念(屏幕 3 帧)——只作认知铺垫,完整展开在 L4 的 RAG 段。

### 1.6 开发环境:命令行、Node/Python、换源

- **命令行导论**(01:11 段):非科班学员"大致要知道哪些命令是干什么的";实际演示覆盖 `pwd`、`ls`、`cd`、`mkdir`、`curl`、`pip`、`npm`(01:11:52 帧簇)。与 L2 的口径一致:常用的就那几个,不必背大全。
- **Node.js / Python 双环境**(01:09 段起):装 Node(涉及 nvm 版本管理)、npm **换国内源 npmmirror**(01:12:41)——网络环境适配是本课程反复出现的现实工程主题。
- 工具生态点名:VSCode、Terminal、Docker(01:30:12,仅提及)、Git/GitHub(仅提及,系统教学在 L2/L3)。

### 1.7 第一个作品:Claude Code 装起来,个人主页跑出来

- 01:17 段起安装 **Claude Code**(本讲屏幕 55 帧,是全营 Claude Code 首秀),配套讲了 **CC Switch**(模型/服务商切换工具,01:11:22 出现)。
- **当堂翻车与修复(有教学价值的事故)**:Windows 机器上装完敲 `claude` 命令**无反应**(01:19:51),讲师现场判断"没有添加环境变量,可能要重启一下终端"(01:20:50),随后果断切到已装好的环境继续演示(01:20:57)——处置思路:先给出诊断方向,不让全班等一台机器。
- 随后用 Claude Code **生成个人主页**(index.html 01:25:44 起,HTML/CSS/JavaScript 元素同段出现):这是全营第一个"一句话让 AI 做出来"的完整作品,也是 L2 方法论的实物预告。React、WebSocket 等名词在此段顺带露面(预告后续)。

### 1.8 课程运营信息(录屏内可证的承诺)

- 01:10:39:"从第五节课开始我们会给大家发一个服务器,Linux 服务器,然后大家就可以用这个 SSH 工具……"(**没有承诺域名**,网传"发域名"无出处)。

## 2. L2 前端与 Skill(7.14)—— Vibe Coding 方法论主场

> 本讲近乎全程录到(99%),183 分钟,是六讲里信息密度最高的一讲。结构大致是:Vibe Coding 心法 → 环境安装攻坚(两段合计 72.4 分钟)→ 前端概念(合计 24.8 分钟)→ Skill 机制与 A/B 验证 → 项目规矩与验收方法论。

### 2.1 Vibe Coding 的角色设定:老板与实习生

- **金句原话**(00:15:13,已逐字核对):"**在 Vibe Coding 中你是一个老板,你把 AI 当成你的实习生,而且是很便宜的实习生。**"
- 配套课件页《把 AI 当实习生》把这套心法结构化(屏幕逐字可读):
  - 总纲:"实习生很勤快,但需要你交代清楚:**做什么、为什么做、不能碰哪里、怎么验收**。"
  - **说清结果**——先描述要交付的页面或功能;"先讲清结果:不要只说'帮我做',要说给谁用、做到什么程度"。
  - **交代现场**——补充项目状态、报错和已有文件;"把项目状态、报错、约束告诉 AI"。
  - **给出边界**——说明不要改哪里、怎样检查完成。
- 这一页是全营方法论的原点:后面 L3 的"数据从哪里来"、L7 的"你要理解智能体的四件套",都是"老板要看得懂下属干的活"这个立场的延伸。

### 2.2 一句话生成网页(实操主线)

- 演示项目:待办清单 `todo.html`(屏幕 24 帧)与 `day2-frontend` 工程;用一句话需求驱动 Claude Code 生成页面,再逐轮改需求看效果。
- 参考了 **v0.dev / v0.app**(Vercel 的 AI 生成前端产品,屏幕 17+23 帧)作为"业界一句话生成页面"的对照。
- 开发服务器跑在 **Vite**(`localhost:5173`),让学员第一次看到"改代码→热更新"的循环。

### 2.3 验收与立规矩(本讲方法论的另一半)

- **验收**(02:50:44):"**AI 很快,但是你必须会验收,你要自己去做这个 leader。**"验收不是看 AI 说了什么,而是自己去点页面、看效果、对结果。
- **立规矩**(02:25:41 起):把**项目规则、常用命令、目录说明写成文件**,让 AI 每次进项目先读——落到 Claude Code 里就是 **CLAUDE.md**(02:16:30 起屏幕 27 帧)。这是把"口头交代"升级为"制度化交代"的一步:规矩写进文件,AI 每次照着做。

### 2.4 Skill 机制与全营第一次 A/B 验证

- Skill = 给 AI 装上一套**领域技能包**(以 `SKILL.md` 为载体,02:33:06 起),本讲用的是自研的前端技能包 `vibecoding-frontend-skill`(屏幕 22 帧)/ `frontend-design`(01:49:45 起 15 帧)。
- **A/B 对照实验**(全营仅有的两次之一):02:41:09 讲师明确"我们的 prompt 其实跟之前没有 skill 的是完全一致的",02:44:28–02:46:18 完成有/无 skill 的效果对比——同一句需求,装上 skill 后生成质量当场可见地不同。方法论上的示范意义:**改一个变量、控制其它变量、当堂看差异**。

### 2.5 前端概念课(约 24.8 分钟,两段)

- HTML/CSS/JavaScript 三件套的分工;React(56 帧)、Vue/Next.js(提及)、TypeScript(01:38:56 起)、Tailwind CSS、组件库 lucide-react。
- **localStorage**(01:52:43 起):数据存在浏览器本地意味着什么——这一点在 L3 被回收:本地存储的局限正是引出"要有后端和数据库"的理由。
- `package.json`、README、`style.css` 等工程文件的作用顺带讲解。

### 2.6 环境安装攻坚(两段合计 72.4 分钟)

这一段占了本讲近四成时长,知识点全是实战网络/系统适配:

- macOS 侧:Homebrew、Node、npm 换源。
- **Windows 专项**(至少 15 处专门指导):00:12:44 "Windows 用户请您使用 PowerShell"(01:04:05 再次强调"不要用 CMD");01:04:13 "**不要在你的 C 盘底下弄,也不要在你的中文路径下弄**";01:11:59 建议放 D 盘或 G 盘;01:10:39 起对具体学员逐个点名排障("某同学,你安装好了吗?""那某同学呢?"),01:13:43 "现在 Windows 的应该也差不多了"。

## 3. L3 后端与多模态(7.15)

> 全程录到(100%),192 分钟,是动手密度最高的一讲。当日项目:**AI 客服系统**(屏幕上项目名 `ai_kefu` / `ai-customer-service` / "烛龙客服"),并且 01:58:05 明确"为了不浪费时间直接用昨天做的那个系统"——**复用 L2 的前端继续往下打通**,课程连续性是设计出来的。

### 3.1 系统链路观(全课灵魂段)

- **金句原话**(00:18:10,已逐字核对):"**我们可以让 AI 负责写所有代码,甚至我们可以不去 review 它的代码,但是我们必须理解:数据从哪里来?到哪里去?失败在哪?**"
- 配套课件《核心能力:看懂系统链路》逐条列出本讲的能力清单(屏幕逐字可读):
  - 解释前端、后端、数据库和模型服务分别负责什么;
  - 安装并验证 Python、uv、MySQL 与 Navicat 环境;
  - 设计并调试 API,读懂请求、响应、状态码和日志;
  - 能指出入口文件、路由、业务服务、数据库配置和依赖的位置;
  - 能沿着一次请求找到前端函数、后端路由或模型调用;
  - 完成登录注册、会话隔离、数据库持久化和真模型对话。
- 这一页等于把"vibe coding 时代还要不要懂技术"的答案写死:**代码可以不逐行看,链路必须能走通**。

### 3.2 API 通识与调试

- HTTP 请求四要素:**Method / URL / Body / Headers**(00:36:10 帧簇);POST 与状态码;**CORS**(00:30:41——前后端分离后绕不开的第一个坑);**SSE**(00:33:56,流式输出,AI 对话产品的标配)。
- 调试工具链:**Apifox**(00:08:46 起,44 帧,本讲主力)、Postman(对照提及)、**Swagger UI / OpenAPI**(00:49:23 起——FastAPI 自带的接口文档,`/api/v1/auth/register` 等端点直接在文档页上试)。
- JSON 作为请求/响应的通用格式(00:23:52 起)。

### 3.3 后端工程:FastAPI 技术栈

- **uv**(00:18:05 起,53 帧):新一代 Python 包管理器,课程标准环境工具;**FastAPI**(00:22:33 起,64 帧)+ **uvicorn**(00:37:53)跑服务。
- 工程分层被显式讲出:入口/路由/业务服务/数据层;**ORM**(00:46:25)与 **SQLAlchemy**(01:29:16)、**Pydantic**(数据校验)。
- **JWT 认证**(00:47:24 起):登录注册、发 token、带 token 访问、会话隔离。

### 3.4 数据库

- **MySQL**(86 帧)+ **Navicat**(00:55:30 起)可视化查表。
- 表设计直接对着项目讲:`users`(00:55:30)、`conversations`(00:56:04)、`messages`(00:55:49)——一个 AI 对话产品最小可用的三张表。
- PostgreSQL、SQLite 作为对照选项被提及(SQLite 在 L7 的 agno 里成为主角)。

### 3.5 AI 的"假完成"(本课程最独特的知识点)

- 01:33:23 讲师当堂拆解:AI 声称做完了后端,实际是"**存在内存数组去假冒数据库**"——页面上一切正常,重启就原形毕露。配套屏幕上有一张**"假完成"对照表**,教学员分辨真做完与装做完。
- 判据被明确给出(屏幕 t≈01:30–01:50 段多帧):**任何"完成"必须被数据证明**——落到本项目就是:**重启后端之后,记录仍然在**(≈01:29:56 帧"重启后端后记录仍在"),数据必须进了真数据库而不是内存。
- 这一段与 L2 的"你必须会验收"闭环:验收的黄金标准不是看演示,是**杀掉进程再看数据**。

### 3.6 排错方法论(4 分 17 秒完整现场)

- **注册接口当堂报 500**(02:00:40)→ 讲师第一句方法论:"**第一步看日志**"(02:01:33)→ 日志里是 `OperationalError (1054, "Unknown column 'users.password_hash' in 'field list'")`(屏幕 OCR 实证)→ 根因讲解:**`create_all()` 只建表、不改表**,从 SQLite 切到 MySQL 时留下了 schema 差异 → 修复后 02:04:57 接口返回 **201**。全程 4 分 17 秒,一次教科书级的"不靠猜,靠查"。
- 另一起真实事故:01:47:42 **Docker 里的 MySQL 与本机 MySQL 误连**(连到了错的实例)——环境里有两个同类服务时的经典坑,当堂澄清。
- 课堂节奏事实(非知识点):02:36:13–02:44:08 有近 8 分钟纯等待(装环境/跑任务),说明实操课的真实节奏。

### 3.7 多模态接入

## 4. L4 知识库与 RAG(7.16)

> 覆盖 95%。本讲是**响应学员反馈的原理补课**:00:01:17 讲师自陈"第二天上课的时候有同学去反映……第一天的 LLM 原理可能不是太清楚",于是前 **114 分钟**(00:00:00–01:54:06)重讲原理,01:54:06 之后进入幻觉与 RAG。全场**零代码、零终端**(屏幕解析证实终端 0 帧、代码编辑器 0 帧),是纯概念课;向量数据库**通篇没有点任何产品名**。

### 4.1 补课段:LLM 工作原理(前 114 分钟)

- **Next Token Prediction** 作为第一性原理(01:17:44 起屏幕出现,贯穿讲解):模型只是在预测下一个词,所有能力与所有毛病都从这里长出来。
- 用 **adamharley.com 的 CNN 可视化**(00:24:09 起,43 帧;CNN 36 帧)做直觉引导——让零基础学员"看见"神经网络逐层在干什么,再类比到语言模型。

- **显存速算**(01:50:36–01:51:29):7B→14GB、13B→26GB、70B→140GB(按每参数 2 字节直乘,**不带** L1 的 1.2 系数——两讲口径不同,引用要注明)。
- 开场 00:04:49 播放了一段行业视频(旁白提及 Codex/GitHub)作为氛围引入。

### 4.2 幻觉的机理(补课段与 RAG 段的枢纽)

- 01:14:30:**用 next token prediction 重新推导幻觉成因**——模型不是在"查数据库",是在"接着说最像的话",所以会一本正经地编。这是 L1 幻觉现象课的机理升级版,也是引出 RAG 的逻辑跳板:既然模型天生会编,就得**把"找依据"这件事交给检索**。

### 4.3 RAG 全链条(02:05:13 起)

- **动机与分工金句**(02:16:00,已逐字核对):"**模型它是负责表达的,检索是负责找依据的。**"一句话把 RAG 的架构讲清:生成与检索各司其职。
- 链条各环节依次展开(屏幕实体与转写互证):
  - **切块(Chunk,02:17:15 起)**:资料怎么切——块太大浪费上下文、太小丢语境;
  - **向量化(Embedding)**:文本变向量,相似度才可计算(承接 L1 的概念铺垫);
  - **召回(Retriever,02:10:26 起)**:先把候选捞回来;
  - **重排(Reranking)**:02:29:05 讲**召回与重排的分工**——召回求快求全,重排求准;
  - **邻块召回防截断**(02:31:17):命中的块要把相邻块一起带上,防止答案恰好被切在块边界上——课程里最"工程细节"的一条 RAG 技巧。
- 插曲:02:28:36 想现场打开 Hugging Face 看现成的 rerank 模型,02:29:22 页面 504 Gateway Timeout,未遂(网络现实第 N 次出场)。
- 定位说明:本讲把 RAG 讲到**原理与设计判断**层;向量库选型不点名、不落代码,代码落地在 L7 的 agno Knowledge(ChromaDb)完成。

## 8. 贯穿全营的方法论主线

把六讲的知识点拉直,有五条互相咬合的主线:

1. **老板—实习生协作观**(L2 起,贯穿到底):AI 是执行者,人负责**说清结果、交代现场、给出边界**;规矩要写成文件(CLAUDE.md/SKILL.md),不靠每次口头交代。
2. **验收高于生成**:"AI 很快,但你必须会验收"(L2)→ 验收的黄金标准是**数据证明**:重启不丢、库里有记录(L3)→ 结构化输出让验收可以机器化(L7 output_schema)。
3. **链路理解不可外包**:"可以不 review 代码,但必须理解数据从哪里来、到哪里去、失败在哪"(L3)——这是全课程对"vibe coding 还要不要学技术"的正面回答。
4. **不靠猜,靠查**:第一步看日志(L3 的 4 分 17 秒现场)→ trace 分清工具错/模型错、调用慢/推理慢(L7)→ 两次 A/B(L2 skill、L7 拔工具)把"感觉"换成"对照"。
5. **幻觉—检索世界观**:模型天生会编(L1 现象 → L4 机理:next token prediction)→ 所以"模型负责表达,检索负责找依据"(L4)→ 落地为知识库/RAG 代码(L7 ChromaDb)。

另有一条隐性主线是**中国网络与本地化工程现实**:npm 换源、科学上网表述、HF 504、DeepSeek/GLM/Qwen 为主力、Windows 路径纪律——贯穿始终的"在真实环境里把东西跑起来"。
