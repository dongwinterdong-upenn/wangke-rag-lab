# 课程目录（章 → 讲 → 节）

这个目录放的是**内容产物**：课程的结构。它不是代码，也不是配置，
而是从课程录屏里读出来的东西 —— 所以它跟代码一样进版本库、跟代码一样要能重跑。

```
db/content/fde_outline.json   ← 四场整录的全部节（97 节，转写取证出来的）
db/content/fde_cut.json       ← 人写的分讲方案：哪些节删掉、哪些节归哪一讲
db/content/fde_lessons.json   ← 生成物。ops/build_lessons.py 出，不要手改
```

现状：**4 章 / 16 讲 / 90 节 / 10 小时 43 分**，每讲 31~48 分钟。

## 一讲 = 片库里的一段片号，不是一场录屏

素材是 4 场各三小时的录屏。一场就是一讲的话，学员一次要坐三个小时。
所以 2026-08-21 把它重切成 16 讲，每讲约 40 分钟。

**没有重新编码一帧。**分片是 10 秒一片、片片以关键帧起头，讲次拿的是片库目录里的
一段（或几段）全局片号，磁盘上 5054 个文件一个都没改名。切点只落在
`fde_outline.json` 已有的节边界上，落到最近的片边界最多偏 5 秒。

一讲可以有【几段】：中间跳过的是剪掉的课间与等 AI 跑完的静音（本次剪掉 61 分钟，
判据见下面「怎么判定死片」）。

### 上一版说「拆不成更多讲次」，那三条后来怎么了

1. **水印位区间在码字发出后不许重排** —— 真原因是位按【讲次顺序】首尾相接分配，
   一重切就整体挪一格。现在改成【全局映射】：`bit(g) = chapter.wm_bit_base + g / stride`，
   只跟"片在哪个目录、第几片"有关，跟它被排进第几讲无关。实测重切前后四个片库的
   `wm_bit_base` 正好是原来四讲的 `wm_bit_offset`（0 / 183 / 375 / 545），
   **每一片对应的码位与重切前逐位相同**，两份已发码字继续有效。
2. **分片按讲次目录从 0 编号** —— 目录归【章】了（章 = 一场录屏 = 一个片库），
   讲次拿片号区间，片名照旧是全局片号。随之而来的是 IV：AES-128 的 IV 一直取
   分片序号，而一讲的第 0 片可能是全局第 267 片，所以播放列表改成逐片显式写 IV。
3. **`learn_progress` 按 (user, lesson) 唯一** —— 旧进度按"播放位置落在新讲的哪一段"
   搬过去（`ops/load_lessons.py`）。`max_position_sec` 搬得精确；`watched_sec` 是
   按各讲已到达时长分摊的近似，代码里写明了它是近似。

## 怎么判定死片

用逐字转写里**显式的 `(静音)` 条目**算占比，不是靠"两条转写之间隔了多久"——
转写条目是多分钟的整段，条目之间的空档是上一条在说话，不是静音。
第一版用后者判，把讲师连讲六分钟的开场判成了空片。

判进 `drop` 的 7 节静音占比都在 84%~97%（课间、等 AI 改完、自行装环境）；
另有 3 处只剪尾巴（`trim`）。每一条在 `fde_cut.json` 里都写了 why。

## 内容是从哪来的

`/home/ubuntu/课程录屏解析/` —— 2026-07-26 那轮三模态解析的产物：
25.3 万字逐字转写、2 分钟粒度的三模态融合块、以及一份已经无缝覆盖全片的内容片段索引。

2026-08-21 在此基础上跑了一轮 4×（起草 → 两条独立判据审稿 → 修订）：

- **起草**：把分析用的碎片按话题并成 12~30 个学员看得懂的节，每节要回转写取证；
- **事实判据**：起点是不是真的落在话题转折上、evidence 是不是逐字存在于起点附近、
  标题说的事在这一段里找不找得到、区间连不连续；
- **文案判据**：《广告法》二十四条（不得承诺学习效果）、绝对化用语、
  敏感信息（录屏里确实有明文凭证）、会议痕迹、术语前后一致。

## 怎么改，怎么重灌

**改分讲方案**（哪几节归一讲、删哪几节）→ 改 `fde_cut.json`：

```bash
python3 ops/build_lessons.py        # 算出 fde_lessons.json，并打出每讲时长/片区间/码位
python3 ops/verify_objects.py       # 把会引用到的每个对象跟 COURSE 上真有的文件对一遍
ops/deploy_lessons.sh --check       # 拿【生产库现状】校验，不写库
ops/deploy_lessons.sh               # 备份 → 迁移 → 灌 → 复核
```

`build_lessons.py` 会在算出结果之前把这些拒掉：某一节既 drop 又排进讲次、
某一节没人要、节号不递增、trim 越出原区间、两讲抢同一片、某讲一个水印槽位都没有。
`verify_objects.py` 拦的是最要命的一种：播放列表引用了磁盘上没有的对象 ——
那不是报错，是 hls.js 无限重试，画面停住而控制台一句话都没有。

**只改某一节的标题/摘要** → 改 `fde_outline.json`，再跑上面那一串（分节会一起重算）。

```bash
ops/preview_outline.py db/content/fde_outline.json > /tmp/outline.md   # 人眼过一遍
```

## 后台为什么不给编辑入口

超管端的讲次列表只**报一个分节数**，没有增删改。
后台能改就等于有了第二个真相来源，它和这份 JSON 迟早会对不上，
而对不上的时候两边看起来都对。要改就改这份 JSON，走上面那条路。

片号区间在后台**只存得下一段**。多段区间（中间跳掉课间的那几讲）在后台的编辑框里
留空才能保存 —— 填了就会把多出来的段整段抹掉，而抹掉之后那一讲照常能播，
只是少了十几分钟，没有任何报错。界面上对这几讲会直接标出来。
